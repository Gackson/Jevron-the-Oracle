# 全屏预言家：视觉与交互草案

日期：2026-09-27。状态：用户已进一步确认串珠门帘首页，并授权开始 iOS 开发。首版工程见 `ios/`，图片提示词见 `ASSET-PROMPTS.md`；以下未注明已验证的参数仍需素材与真机验证。

## 1. 用户已明确的方向

- 原生、简约，同时具有神秘感、深度、质感。
- 每个角色的场景铺满屏幕，陀螺仪驱动深度感；不同角色可有不同的视觉复杂程度。
- 中心清晰，接近边缘逐渐模糊并轻微拉伸，产生梦幻观感。visionOS 是观感参考。
- 首次可以经过主界面，再次进入直接到对话。
- 左右切换预言家，通过输入框直接对话。
- 简短回应出现在页面中下方中央，逐词出现，新词可以发光。
- 支持继续对话。新回应替换当前展示，上下滑动可访问历史。

## 2. 建议的视觉结构

场景假设：用户在晚间的室内拿起手机，带着一个未解的问题，短暂进入一个安静而陌生的空间。以暗调场景推进第一版，日间与高亮环境的可读性仍需验证。

采用克制配色：低彩度中性色承担界面，角色素材承载局部暖光、冷光或暗红。色彩 token 后续用 OKLCH 定义并验证对比度；本轮不冻结未经试样的色值。

从后到前分为三个职责层：

1. **空间**：背景、角色与可选前景，同一画布分层，小幅相对位移表现纵深。
2. **光学处理**：只处理场景，中心保留细节，四周渐进虚化并轻微向外拉伸。脸、石碑关键边缘、面具表情避开强变形区域。模糊和拉伸是独立效果，不声称仅凭分层位移就能得到。
3. **固定界面**：角色名、回应、输入框与导航固定在屏幕坐标，保持清晰；中下部场景亮度收敛，为文字提供稳定衬底。

角色可以延伸到屏幕边缘，但主体识别区域保持安全。无外部卡片、舞台镜框或海报边界。系统控件的材料仅服务可读性与操作。

建议静止时也有轻微的边缘光学处理；倾斜只温和改变层间位置。先分别验证静态构图、视差和边缘效果，再合成，避免多种运动叠加造成晕动。

### 角色差异

| 角色 | 复杂度与质感 | 视觉重心 |
| --- | --- | --- |
| Oracle | 生活细节较丰富，暖侧光、人物与织物 | 从容的表情与坐姿，少量桌面物件，亲近而难以看透 |
| Stone | 最简洁，黑色竖碑、明确的面与阴影 | 重量、比例、留白，边缘不能与背景完全融为一体 |
| Jester | 中等复杂度，不对称面具、釉面或彩绘质感 | 微妙的表情偏差，少量骨白和暗红，避免大量装饰物 |

共同标准是可信材质、光线精度和完整空间。Oracle 保持已有的人物方向，不因统一质感擅自改为雕塑。

## 3. 入口和主布局

主界面已确定为简短产品介绍与调性建立：完整串珠门帘背景、产品名、简短介绍、一个进入按钮。点击后简介淡出，播放门帘打开的视频，衔接 Oracle 所在房间。首尾帧的图片提示词与视频提示词已提供，视频由用户后续制作。进入后默认 Oracle，不自动申请麦克风权限。

再次启动建议直接进入上次所选角色；没有选择记录时进入 Oracle。角色偏好和是否完成首次进入可本地保存，与对话内容的持久化分开。顶部保留轻量返回主界面的入口。

对话布局：顶部仅保留必要导航及角色身份；中心属于角色；中下部为当前回应；底部安全区上方为固定输入框，含语音与发送动作。首次尚未提问时，回应位置显示一句简短邀请。

纵向位置以可用空间分配，不固定死在某个屏幕百分比。键盘出现时，场景继续满屏铺底，输入框随键盘上移，回应让出阅读和编辑空间。小屏与大字号允许布局重排。

## 4. 会话链路与状态

首次主界面 → 默认 Oracle → 输入或语音转写 → 编辑确认 → 提交 → 等待 → 逐词显现 → 继续提问。

| 状态 | 展示与动作 |
| --- | --- |
| 首次空会话 | 角色名、一句邀请、输入框；无额外教程轮播 |
| 输入 | 已有回应保持可读；语音停止后可编辑，再明确发送 |
| 等待 | 保留上一条回应并降低视觉强调，给出新的等待状态；首次则只显示等待提示。禁止重复发送，允许取消 |
| 新回应到达 | 将上一轮保留到历史，新回应在同一位置开始显现。用户正在回看历史时不强制跳转 |
| 完成 | 光晕退去，稳定文字可读，输入框继续可用 |
| 失败 | 保留问题草稿与已有历史，显示具体恢复入口；未完成片段明确标记，不视为完整回应 |

每位角色建议拥有独立的会话、草稿与历史位置。切换角色时取消当前录音或未完成请求，保留已有完整轮次；迟到的结果不得覆盖另一位角色。

## 5. 双轴浏览

- 左右：切换角色；主要从场景空白区域识别，同时提供可点击、可被 VoiceOver 使用的切换入口。
- 上下：翻看当前角色的轮次。每页是一轮简短回应，历史轮次附带弱化的问题与时间上下文，不扩展成密集气泡列表。
- 较早轮次位于最新轮次上方。背景角色保持当前角色，不随翻页重复进场。
- 手势识别锁定主要方向，斜向滑动一次只执行一种动作；输入编辑、文本选择和键盘操作优先。
- 历史状态出现“回到最新”入口；输入框建议仍用于继续最新会话，明确提示这一点，避免让用户误以为正在从旧消息分支。
- 回看时不重播逐词动画；新结果到达只提示可查看，避免抢走阅读位置。

会话内历史属于这条核心交互的一部分。跨重启恢复完整对话尚未由用户明确，本轮建议暂不默认持久化原始问题；如需要恢复，需把本机保存与删除一并纳入设计。它与未来主动收藏的 Echoes 不同。

## 6. 逐词显现与发光

目标是词语到来的灵动反馈，而不是不断闪烁。

- 新词轻微由虚到实，短暂带柔和光晕，随后收敛为稳定文字；已出现的词保持位置和亮度。
- 新词出现时避免整句重新居中、左右跳动。完整答案已知时先计算最终文本布局，再按词显现。
- 节奏按词长与标点调节，总时长设上限；输入、取消和导航不等待动画结束。提供直接显示完整回应的操作。
- 默认以单行作为构图目标。较长短答、小屏、Dynamic Type 时允许两行或更多，禁止靠无限缩小字体、截断或跑马灯维持单行。
- 逐词单位只是视觉呈现，不改变候选原文、词序和标点。Jester/Stone 的片段分隔仍需遵循确定性呈现规则。
- Reduce Motion 下直接显示，取消视差、拉伸变化和入场位移；VoiceOver 在完整结果就绪时读出一次，不逐词反复播报。

## 7. 素材交付变化

原先约占页面四成的舞台构图，需要改为覆盖全屏长画幅的场景。素材须同时验证中心主体、四边延展、中下部文字可读区以及底部输入区。

保留“完整母图 + 补全背景 + 透明主体 + 可选前景”的制作流程。所有图层同画布、同坐标，统一裁切。光学效果施加在场景合成后，不能把虚化和发光烘焙进文字资产。

正式画布尺寸和 overscan 待目标设备比例、最大位移及边缘变形范围试验后确定。旧契约 1536×2048 / 1.12 倍外扩不是新全屏构图已验证的结论。母图仍提供静态与性能降级版本。

## 8. 相对旧计划的工程变更

| 原规划 | 最新方向需要的调整 |
| --- | --- |
| 页面内的有限高度舞台 | 全屏场景，固定界面，键盘与大字号布局适配 |
| 单次问答 P0，一次追问 P1 | 连续对话进入核心链路，需要上下文关联与每角色会话状态 |
| Echoes 才能回看 | 当前会话先有轮次历史，收藏和长期保存另定 |
| 一次完整 JSON 返回 | 可先支持完整结果的逐词视觉显现；真实生成中逐步到达需另设计流式协议 |
| 主要是分层位移 | 增加独立的边缘虚化、轻微拉伸与性能降级策略 |

当前 Oracle 的机制是一次选择完整短答，Stone/Jester 是逐步选择词组，并非三者都逐词生成。建议第一版保持这些内容机制，先验证逐词呈现的体验。如果需要等待中就看到真实到达的片段，需另行定义事件、顺序、终止与中断行为；不能把显示动画称为服务端实时生成。

连续对话还需扩展请求中的上下文。建议先保留当前角色最近若干完整轮次，并为上下文设明确预算；具体窗口、请求字段、服务端校验和状态版本须在实现前更新共享契约。三位角色仍遵守既有的有限语言与长度规则。

旧文档的四小时排期不自动覆盖这些新增工作。原 v1 协议保持不变；iOS 目前按 `IOS-CONVERSATION-API.md` 的 v2 草案携带连续对话上下文，服务端仍待对接。
