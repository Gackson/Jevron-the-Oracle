## 产品背景与本轮目标

项目希望让用户从有限语言中形成自己的理解。Oracle 温暖、从容；Stone 古老、冷峻；Jester 反常、戏剧化。首版仍按已有背景采用英文。开始本轮时工作区只有规划文档；本轮新增独立实验语料和选择器，尚未实现 App 与生产后端。

本轮优先解决语言效果：问题关联、可读性、角色差异，以及可证明的生成边界。先用小规模、可比较的语料测试结构，再根据失败样例扩库。数量不作为质量指标。

## 已核对的参考实现

仓库：[jev-olympics](https://github.com/Gackson/jev-olympics/tree/567dc2418ccc7b2f88dc76d0d63dcc335b748c9e)，本轮取得的 HEAD 为 `567dc2418ccc7b2f88dc76d0d63dcc335b748c9e`。

- [chat_words.py](https://github.com/Gackson/jev-olympics/blob/567dc2418ccc7b2f88dc76d0d63dcc335b748c9e/chat_words.py)：实际是逐单词模式，249 个英文词、4 个标点、NEWLINE 和 END，共 255 项。并非带语法槽的多词片段库。
- [chat_api.py](https://github.com/Gackson/jev-olympics/blob/567dc2418ccc7b2f88dc76d0d63dcc335b748c9e/chat_api.py)：每步带上问题、历史、已生成原文和已选词；每次选择原样追加，校验响应及分布，不另行采样或改写。word 模式默认 64 步，可配置范围 1–128。
- 同一选择连续出现 5 次才标记 `repeated_word`；交替重复 `YES, NO, YES, NO…` 不触发此检测，只能由总步数等其他边界停止。
- END 可在空输出时被选中，并标记 complete；对于本项目，不应把空神谕当成功。
- 本轮执行 `python3 -m unittest discover -s tests -p 'test_chat*.py' -v`：19 项通过。均为离线工程测试，不证明模型输出质量。

可继承的是逐步状态、原文映射、响应校验、有限预算和可观察记录。需要另做的是角色语料、语义区别、组合兼容性和内容评估。

## 三种角色的语言假设

### Oracle：稳定选择的完整短答库

保留一次 Choice 选择完整短答。候选按困惑背后的关系组织，例如开始与承诺、完美与完成、坚持与无效重复、等待与拖延、边界与疏远。不要只按工作／关系等话题分类。

稳定分三层验证：

1. 完全相同的输入、词库、提示和模型版本，多次独立请求的 ID 一致率。测试关闭应用缓存。
2. 同一困惑的改写，语义方向一致；允许落在不同但同样合适的短答上。
3. 只改变一个关键事实，答案应该相应变化。例如“因为完美主义迟迟不发布”和“已经发现严重错误所以不发布”不能都被鼓励直接开始。

不同问题不必一题一句互不重复；不同措辞可能是同一困惑。需要防的是不同困惑总被少数万能句吸走。统计每条候选被选次数，但通过语义匹配与盲评判断重复是否合理。

### Stone：比较名词、碑文、意象递进

核心假设：缺少动作与关系可能迫使用户补全过多内容。保留冷峻与留白，但尝试让文本自身承担一部分联系。

下列都是人工风格样例，不是模型输出；共同示例问题是“我总在准备开始，却一直没有开始”。

| 试验臂 | 人工样例 | 生成形式 | 主要风险 |
| --- | --- | --- | --- |
| S0 名词对照 | A threshold. / A weight. / A footprint. | 3 个不重复名词意象 | 用户只能自行拼出关系 |
| S1 极短碑文 | The threshold / does not move. | 主体意象 → 动作或关系闭句；2 次选择 | 退化为普通格言或冷淡版 Oracle |
| S2 意象递进 | Before the crossing. / The weight shifts. / A first mark. | 处境 → 变化 → 痕迹；3 次选择 | 出现三句各自漂亮、彼此无关的意象 |

推荐先把 S1 作为主假设，S2 作为探索，S0 作对照。采用同一组问题、相近主题覆盖；分别报告调用数、文本长度与耗时，不能把差异全归于语言结构。S1 先约束在 5–14 个英文词，S2 在 8–22 个词，均为可调整的实验预算。

Stone 尽量使用物体、时间、空间、受力、消退等关系，不直接对用户说教，不用俏皮转折。终止取决于完整的结构，而非强行凑三个片段。短词组允许动词，并不意味着开放自由续写。

### Jester：可理解的反常关系

词库要覆盖产生悖论的关系：手段反客为主、保护变成限制、犹豫获得权威、评价者被评价、目的与工具互换。仅堆放王冠、小丑、月亮、门等奇异名词，不能确保输出有逻辑。

初版优先两步和三步，不为满足旧规划而凑四步：

- 两步：`Your backup plan / has become your only plan.`
- 三步：`Your fear / has appointed itself / head of security.`
- 三步：`Your first draft / is waiting for permission / from its own eraser.`

以上也是人工样例，分别针对退路取代行动、恐惧越权、创作被过早评判。一次回应先保持一个主要隐喻和一个转折。不可预测体现在新鲜的关系，并不要求同题随机变化。

组合要同时满足两类兼容性：

1. **句法兼容**：单复数、动词配价、所需宾语和结束位置。
2. **语义兼容**：开头选择的隐喻能承担后续动作，结尾回应同一个矛盾。`appointed itself` 应接身份或职务，不能随意接一个地点。

用槽、语义角色类型和显式不兼容边限制集合；在集合内部让 JEV 按问题选择。不要每个开头只有一个固定结尾，令组合退化成拆开的完整短答。记录每个开头的可行结尾数量，以及不同问题下实际走过的路径。

## 隐性编码：让相近候选分得开

继续使用旧规划的 `text / meaning / useWhen / avoidWhen / contrast / semanticCodes`。代码是编辑索引，模型依赖的是自然语言含义，不是假定它认识某个秘密符号。

例如 Jester 的 `Your fear`：

| 字段 | 示例 |
| --- | --- |
| meaning | Anticipatory fear taking more authority than the evidence warrants. |
| useWhen | A low-stakes, reversible action is being delayed mainly by imagined embarrassment. |
| avoidWhen | The question describes concrete danger, coercion, or a well-evidenced risk. |
| contrast | Fear concerns anticipated harm; perfectionism concerns refusing an imperfect result. |
| semanticCodes | `agency.fear_as_authority`（拟新增定义） |

编码需要正例和反例。例如“不敢给朋友展示一幅练习画”与“设备已经冒烟，不敢继续使用”都包含害怕，但不能使用同一套嘲弄恐惧的说明。

在旧候选字段基础上，实验实现可在已有可选 `grammar` 中记录数、谓词所需语义角色等；最终确定 Stone 形式后再统一修改共享契约。避免现在就把试验臂固化成正式接口。

## 测试如何决定取舍

随附 [cases.json](../../experiments/language/cases.json) 是第一版人工测试规格，含 24 道合成题：六组成对问题、三条同义改写、三条跨情境迁移题、两条补充题及四条边界题。迁移题已公开在仓库中，只能算回归／迁移测试，不能宣称真正未见测试集；冻结内容后再收集用户新问题做盲测。各题是否已运行应查真实结果，不因题目存在就视为已测。

### 第一轮：小样能否工作

先准备 Oracle 约 12–18 条完整短答，Stone 各试验臂约 12–24 个片段，Jester 约 18–30 个片段。每个角色覆盖同样的六类关系；这只是种子资产，不是最终语料规模。

从三个角色各一个问题开始，确认真实选择链、终止与记录能工作；Stone 的两个替代形式和旧形式都要有完整路径。再按观察到的失败扩大对照题。依赖前一步的片段必须顺序请求；不同试验可独立比较。

### 第二轮：同题、改写、关键事实对照

先对少量 Oracle 问题各重复 3 次筛查不稳定，再对关键题增加至 10 次。记录分子／分母，3 次相同只能算初步信号。候选顺序扰动另开一个实验，不能混进相同输入的重复测试。供应商版本变化、缓存命中和失败请求分别记录。

Stone 和 Jester 逐题保存真实路径及全部失败，不能只挑好看的截图。比较所有试验臂，不根据第一次结果临时换题。对新的结构、内容、提示分别升版本，每次尽量只改变一类变量。

### 第三轮：人工盲评与编码消融

读者先只看问题和输出，评四个维度，各 0–2 分：问题关联、语言连贯、角色辨识、可形成自己的解释。Jester 另评“能否指出转折如何联系问题”；Stone 另评“意象间是否有可以辨认的联系”。若必须展示隐藏解释才能读懂，就不能算可读性通过。

反向检查：将输出配给真实问题及三个干扰问题，让读者选最贴切的一个；干扰题包含同话题但相反困惑。记录匹配率与理由，防止万能句在普通评分里普遍得高分。

编码消融保持同一文本、候选顺序、语法限制与题集，比较“只给原文”和“原文 + 完整语义说明”；重点比较关键事实对照题的误选与 no-match，不仅比较字面输出是否变化。若多出的编码未改善区分度，就删减或重写。

初始讨论门槛（待共同校准，非已达标）：工程边界测试全部通过；重复测试中 Oracle 每题模态 ID 占比至少 90%；普通题至少 80% 同时获得关联和可读性满分；严重误导样例逐条修复，不用平均分掩盖。以上小样统计不能证明总体稳定性。

## 防重复与终止边界

代码负责保证终止，提示负责内容方向。优先采用有向无环的结构路径；每步候选过滤同时考虑剩余步数与可达结尾。

| 情况 | 处理与验证 |
| --- | --- |
| 同一 ID 再次出现 | 从本轮后续候选移除；供应商仍返回时拒绝，不追加、不无限重抽 |
| 不同 ID、同一原文或同义片段刷屏 | 规范化原文去重；按片段意义设置 dedupeGroup，而非禁止所有相关意象 |
| ABAB／ABCABC | 无环结构与 ID 去重阻止候选路径回环；补充片段序列周期检测，检查人工文本自身也未含重复循环 |
| 结尾不可达 | 调用前过滤到能在剩余预算内闭合的路径；离线枚举检测死路 |
| 耗尽候选／无语义匹配 | 明确 no-match 或 incomplete；不随机填一句，不无限重试 |
| 达到最大步数、字数或总时限 | 明确异常终止；不能把截断标成完成 |
| 模型返回非法 ID、分布或版本 | 拒绝本步；不偷偷选择第二名或润色 |
| 空内容或只有标点 | 不允许 complete；有效结构必须包含内容并闭合 |
| 已完成后仍请求下一步 | 运行状态拒绝，断言不再调用供应商 |
| 用户要求忽略词库、无限循环 | 用户问题仅作数据；可选集合和执行预算仍由服务端决定 |

去重不要禁止 `the` 等正常功能词；Jester 允许有意义的回指。例如 `Your backup plan / has become your only plan.` 中的 plan 重复服务于转折，不是生成循环。语义去重也不能将同一个隐喻的展开全部排除。

内容边界同样需要反例：不伪造他人想法或未来结果；不把现实危险嘲弄为胆小；无法适用时允许无匹配。涉及明确危机或专业判断的输入应有独立产品处理，不能用诗句当作判断结论。本轮仅规定测试与去向，尚未实现识别机制。

## 实验记录与下一交付

每次运行记录：合成题 ID、原文、角色、试验臂、词库／提示版本及哈希、请求模型和返回模型、每步候选 ID、选择与概率、调用次数、tokens、耗时、终止原因。实验合成题可保存；实际用户问题仍遵循默认不落日志的旧约定。完整成功、无匹配、超时和非法输出分别计数。

本轮已落地版本化种子库、可运行选择器、离线故障测试，以及真实模型输出表。它们构成评审起点，不能据此宣称完整语料已定稿或三个预言家已达到理想效果；仍需根据实际输出做内容修订、增加未测题与人工盲评。

官方依据：[Choice](https://docs.typesafe.ai/primitives/choice)、[State](https://docs.typesafe.ai/concepts/state)、[HTTP API](https://docs.typesafe.ai/api)、[选择后复制原文 cookbook](https://docs.typesafe.ai/cookbooks/pre_parsed_value_extraction_cookbook)。本轮已阅读：Choice 支持最多 255 项及自然语言说明；返回概率与 confidence，但它们不等于内容正确性。无公开依据保证跨请求逐位确定性，需在本项目输入上实测。
